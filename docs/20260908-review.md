# Code readability review — 2026-09-08

The module boundaries are sensible. The biggest readability gains would come from clearer formatting, simpler configuration parsing, and more explicit lifecycle ownership.

These findings are ordered by expected readability benefit.

## 1. Expand the demo template and CSS

The entire playground occupies one line in [demo/App.vue](../demo/App.vue#L295), and [demo/style.css](../demo/style.css#L31) compresses substantial rules into single lines. This hides nesting, makes bindings difficult to scan, and produces noisy diffs. Format elements, attributes, and declarations consistently before considering component extraction.

## 2. Stop tests from enforcing source formatting

[demo/main.spec.ts](../demo/main.spec.ts#L113) requires an exact configuration string; line 160 requires an exact CSS rule. Harmless formatting or helper extraction breaks these tests. Prefer assertions against configuration values, rendered elements, and behavior. These tests currently obstruct readability improvements.

## 3. Separate configuration validation from default resolution

[src/nyx-fission.ts](../src/nyx-fission.ts#L25) mixes general validation with returning resolved luma-key settings. Repeated object checks and nested ternaries make the accepted inputs hard to understand. Extract `resolveLumaKeyConfig`, validate its shape with guard clauses, then apply defaults explicitly. Preserve the distinction between omitted values and invalid values such as `null`.

## 4. Centralize resource cleanup

[destroy()](../src/nyx-fission.ts#L141) and [fail()](../src/nyx-fission.ts#L257) repeat the same cancellation, disposal, and reference clearing. Readers must compare both blocks to establish whether cleanup differs. Extract a private `releaseResources()` method while keeping state transitions, promise rejection, and event emission explicit in each caller.

## 5. Consolidate the numeric input lifecycle

[demo/App.vue](../demo/App.vue#L78) repeats input updates, debounce scheduling, timer cancellation, and committing for three controls. A small `useDebouncedNumberInput` helper would expose each control’s actual policy more clearly. Keep parsing configurable: depth currently treats an empty input differently from threshold and coherence.

## 6. Make asynchronous names and boundaries truthful

[demo/App.vue](../demo/App.vue#L183) declares `createInstance` as `async`, but it never awaits readiness. Callers’ `await createInstance()` therefore looks more meaningful than it is. Make setup synchronous and name it accordingly, or explicitly await `nextInstance.ready` if readiness is the intended contract.

## 7. Remove unnecessary indirection in media disposal

[src/media/source.ts](../src/media/source.ts#L44) names a function `disposeUrlImage` even though it creates a disposer. Use `createImageDisposer` and `createVideoDisposer`. At [line 308](../src/media/source.ts#L308), replace the immediately invoked function returning another function with `dispose: () => dispose()`.

## Scope and validation
